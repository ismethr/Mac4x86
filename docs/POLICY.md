# 许可与收录规则

本文写给维护者自己，也写给来这里查看的上游作者：这个仓库收什么、不收什么、每次发布要满足哪些条件。

> 这里只是按常见理解整理的操作规范，不是法律意见。遇到拿不准的许可证，就先不收。

## 收录标准

一个软件要同时满足下面几条才收录：

1. **上游没有官方 Intel 版本**（包括 Universal 版本）。如果上游提供了，就直接指向官方。
2. **许可证是 OSI 认可的开源许可证**，允许修改和再分发（见下表）。
3. **能从公开源码构建出来**，不依赖上游私有的密钥、服务端或二进制。
4. **上游没有明确反对**非官方构建。README、Issue 或讨论里表示过反对的，不收录。

## 许可证对照表

| 许可证 | 能否收录 | 额外要求 |
| --- | --- | --- |
| MIT、BSD-2/3、ISC、Zlib | 可以 | 发布包里附上原版权声明和许可证全文 |
| Apache-2.0 | 可以 | 附上 `LICENSE` 和上游的 `NOTICE`（如有）；修改过的文件要注明改动；许可证不授予商标权 |
| MPL-2.0 | 可以 | 改过的 MPL 文件以 MPL 公开源码（fork 仓库即可满足） |
| LGPL-2.1 / 3.0 | 可以 | 公开对应源码；用户要能替换 LGPL 库（动态链接最省事） |
| GPL-2.0 / 3.0、AGPL-3.0 | 可以 | 整个 fork 必须同样以 GPL 发布，不能附加限制；每个二进制都要能拿到**完全对应的源码**，包括构建脚本 |
| BSL、SSPL、Elastic、PolyForm、带 Commons Clause 的许可证 | **不收** | 这些许可证不是开源许可证，通常禁止或限制再分发 |
| 没有 LICENSE 文件 | **不收** | 没有许可证就是保留所有权利，不能再分发。可以先去上游问能否加许可证 |
| 「仅供个人使用」、自定义许可证 | **不收** | 除非得到作者书面同意，并把同意记录链接放进 x86 仓库 |

**依赖也要看。** 应用打包进去的第三方库（框架、字体、图标包等）同样受各自许可证约束；GPL 依赖会让整个应用必须按 GPL 发布。

## 每次发布的清单

每个 x86 仓库发布新版本前，逐项确认：

**许可证与版权**
- [ ] 仓库根目录的 `LICENSE` 保留上游原文，原版权行不改，另加一行自己的版权（例如 `Copyright (c) 2026 ismethr (x86 fork modifications)`）。
- [ ] **发布包里带上许可证**：把 `LICENSE`（以及 `NOTICE`、第三方依赖的许可证）放进 `.app/Contents/Resources/`，在 zip 根目录也放一份。MIT 等许可证要求「所有副本」都附带声明，二进制也算。
- [ ] Release 说明写明：上游仓库和版本 tag、原作者、许可证名称。
- [ ] 每个 Release 对应一个 git tag，GitHub 自动生成的源码包就是对应源码。GPL 软件要确认构建脚本也在仓库里。

**不冒充官方**
- [ ] 名称带「x86」或「Intel」，README 和 Release 说明第一段写明「非官方，与原作者无关」。
- [ ] **改掉 Bundle Identifier**，不沿用上游的（例如 `com.oiloil.find` 改成 `io.github.ismethr.oilfind-x86`）。沿用上游 ID 容易让人以为是官方版本，也会和官方版共用系统权限记录和偏好设置。改 ID 后旧设置不会自动带过来，需要在 Release 说明里提醒用户重新授权。
- [ ] 关闭或改写上游的自动更新，不能让 x86 版本下载上游的 arm64 包，也不能借用上游的更新签名密钥。
- [ ] 「关于」窗口、崩溃反馈、意见反馈等链接改成指向 x86 仓库。
- [ ] 不在官网、商店页面等地方使用上游的 logo 做宣传。应用自带的图标可以保留；上游要求更换时就换。

**安全与可信度**
- [ ] 尽量用 GitHub Actions 公开构建，或者至少公开完整的构建命令。
- [ ] Release 说明附上 SHA-256。
- [ ] 改动只限于让软件在 Intel 上运行或修 bug，不加广告、统计或联网功能。所有改动都能在 fork 的提交记录里看到。

## 与上游的关系

- 能合进上游的改动（比如 x86 的编译修复），优先向上游提 PR。上游愿意官方提供 Intel 版本，对所有人都更好。
- 上游开始官方提供 Intel 版本后，在列表里标成「已有官方版本」，停止更新，并把 x86 仓库归档。
- **下架**：上游作者通过 Issue 或邮件提出异议，7 天内删除对应的 Release 并在列表中移除，不需要讨论理由。
